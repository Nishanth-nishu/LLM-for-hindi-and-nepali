## Reproduction Steps

### Prerequisites

```bash
pip install datasets sentencepiece datasketch fasttext langdetect \
            trafilatura pytesseract pdf2image Pillow pyyaml tqdm \
            matplotlib requests
# Tesseract OCR:
sudo apt-get install tesseract-ocr tesseract-ocr-hin tesseract-ocr-nep poppler-utils
# fastText language ID model:
wget https://dl.fbaipublicfiles.com/fasttext/supervised-models/lid.176.bin

# Only needed for Step 3b (LLM quality repair of manual data, Yi model):
pip install transformers accelerate bitsandbytes torch
```

### Step 1 ??? Source Reconnaissance (do this FIRST, before bulk download)

```bash
# Hindi
python common/preprocessing/recon.py --lang hindi --repo-root project/
python common/preprocessing/recon.py --lang hindi --inspect-feature lang_id_confidence \
    --fasttext-model lid.176.bin

# Nepali
python common/preprocessing/recon.py --lang nepali --repo-root project/
python common/preprocessing/recon.py --lang nepali --inspect-feature devanagari_ratio
```

After running recon, **fill in all `null` threshold values** in:
- `hindi/configs/filtering_thresholds.yaml`
- `nepali/configs/filtering_thresholds.yaml`

### Step 2 ??? Download Public Corpora

```bash
# Hindi (test with small sample first)
python project/hindi/data/download_public.py --source wikipedia --max-docs 1000 --repo-root project/
# After verifying output, download all enabled sources:
python project/hindi/data/download_public.py --source all --repo-root project/

# Nepali
python project/nepali/data/download_public.py --source all --repo-root project/
```

### Step 3 ??? Manual Collection

```bash
# OCR (point at a directory of PDFs/images)
python common/preprocessing/ocr_ingest.py --lang hindi \
    --input-dir /path/to/pdfs/ --repo-root project/

# Scraping (requires seed_urls.txt)
python common/preprocessing/scrape_ingest.py --lang hindi \
    --url-file project/hindi/data/raw/manual/scrape/seed_urls.txt --repo-root project/

# Transcription
python common/preprocessing/transcription_ingest.py --lang hindi \
    --input-dir project/hindi/data/raw/manual/transcription/ --repo-root project/
```

### Step 3b ??? LLM Quality Repair for Manual Data (Yi model)

Manually-collected text (OCR especially) is much noisier than the downloaded
corpora. Before it enters the shared cleaning pipeline, run it through
`llm_quality_repair.py`, which uses a Yi model (`01-ai/Yi-1.5-*-Chat`) to fix
OCR/scrape damage ??? broken characters, mid-word line splits, running
headers/footers ??? without paraphrasing or inventing content, and to drop
documents that are unsalvageable. This is a **generative repair pass on
manual data only**; it never touches the downloaded corpora, which are
already clean machine text.

```bash
# Smoke test on a handful of docs first:
python common/preprocessing/llm_quality_repair.py --lang hindi \
    --input  project/hindi/data/raw/manual/ocr/hi_ocr_raw.jsonl \
    --output project/hindi/data/raw/manual/ocr/hi_ocr_llm_repaired.jsonl \
    --repo-root project/ --model 01-ai/Yi-1.5-6B-Chat --use-4bit --dry-run 20

# Full run (drop --dry-run once the smoke test looks right):
python common/preprocessing/llm_quality_repair.py --lang hindi \
    --input  project/hindi/data/raw/manual/ocr/hi_ocr_raw.jsonl \
    --output project/hindi/data/raw/manual/ocr/hi_ocr_llm_repaired.jsonl \
    --repo-root project/ --model 01-ai/Yi-1.5-6B-Chat --use-4bit
```

Repeat for the scrape and transcription outputs, and for Nepali. Use the
larger `01-ai/Yi-1.5-9B-Chat` (no `--use-4bit`, needs more VRAM) if you have
a bigger GPU than a free-tier Colab T4; the 6B + 4-bit combination is what
fits a free T4 (~15GB VRAM).

The script is resumable (re-running with the same `--output` skips
already-processed doc_ids) and writes an audit trail ??? every
(original, repaired) pair and every rejection ??? to
`<lang>/data/raw/manual/llm_repair_audit.jsonl`, plus a random sample to
`report/llm_quality_repair_audit_sample_<lang>.json` for the Phase-1 report.
Feed `*_llm_repaired.jsonl` (not the raw ingest output) into Step 5's
`lang_id_filter.py` for manual sources.

### Step 4 ??? Freeze Test Holdout (BEFORE any cleaning)

```bash
python common/preprocessing/test_holdout.py --lang hindi --repo-root project/
python common/preprocessing/test_holdout.py --lang nepali --repo-root project/
```

### Step 5 ??? Cleaning Pipeline (per language, per source JSONL)

```bash
# Run for each raw JSONL file, e.g. hi_wiki.jsonl:
python common/preprocessing/lang_id_filter.py \
    --lang hindi --input project/hindi/data/raw/downloaded/hi_wiki.jsonl \
    --output project/hindi/data/cleaned/hi_wiki_langid.jsonl \
    --fasttext-model lid.176.bin --repo-root project/

python common/preprocessing/normalize.py \
    --lang hindi --input project/hindi/data/cleaned/hi_wiki_langid.jsonl \
    --output project/hindi/data/cleaned/hi_wiki_normalized.jsonl --repo-root project/

python common/preprocessing/boilerplate_strip.py \
    --lang hindi --input project/hindi/data/cleaned/hi_wiki_normalized.jsonl \
    --output project/hindi/data/cleaned/hi_wiki_boilerplate.jsonl

python common/preprocessing/quality_filters.py \
    --lang hindi --input project/hindi/data/cleaned/hi_wiki_boilerplate.jsonl \
    --output project/hindi/data/cleaned/hi_wiki_quality.jsonl --repo-root project/
```

### Step 6 ??? Deduplication

```bash
python common/preprocessing/dedup_exact.py \
    --lang hindi --input project/hindi/data/cleaned/hi_wiki_quality.jsonl \
    --output project/hindi/data/dedup/hi_wiki_exact.jsonl

python common/preprocessing/dedup_paragraph.py \
    --lang hindi --input project/hindi/data/dedup/hi_wiki_exact.jsonl \
    --output project/hindi/data/dedup/hi_wiki_para.jsonl --repo-root project/

python common/preprocessing/dedup_near.py \
    --lang hindi --input project/hindi/data/dedup/hi_wiki_para.jsonl \
    --output project/hindi/data/dedup/hi_wiki_near.jsonl --repo-root project/
```

### Step 7 ??? Safety Filter + Decontamination

```bash
python common/preprocessing/semantic_safety_filter.py \
    --lang hindi --input project/hindi/data/dedup/hi_wiki_near.jsonl \
    --output project/hindi/data/dedup/hi_wiki_safe.jsonl --repo-root project/

python common/preprocessing/decontaminate.py \
    --lang hindi --input project/hindi/data/dedup/hi_wiki_safe.jsonl \
    --test-holdout project/hindi/data/test_holdout/test.jsonl \
    --output project/hindi/data/decontaminated/hi_wiki_decontam.jsonl --repo-root project/
```

### Step 8 ??? Train/Val Split

```bash
python common/preprocessing/split_data.py \
    --lang hindi --input project/hindi/data/decontaminated/hi_wiki_decontam.jsonl \
    --repo-root project/
```

### Step 9 ??? Train Tokenizer

```bash
python common/preprocessing/train_tokenizer.py \
    --lang hindi --repo-root project/
```

Then **fill in** `hindi/configs/tokenizer_config.yaml: final_vocab_size` with your chosen value.

## Threshold Setting Protocol

Every threshold in `filtering_thresholds.yaml` starts as `null`.
Before the pipeline is considered compliant, each threshold must be:
1. Determined from the corpus distribution (via `recon.py --inspect-feature <name>`).
2. Manually reviewed on ??? 50 borderline examples.
3. Recorded in the YAML with a `rationale` field.

Scripts warn when running with null (fallback) thresholds.

## Manual Fraction Compliance

The 20% manual fraction is evaluated on the **final tokenized training corpus**
(not raw byte counts). `compute_stats.py` reports a PASS/FAIL against this
requirement. If FAIL, the output states exactly how many more manual tokens are needed.

### Target split (both languages)

| | Target tokens (post-cleaning) | Source |
|---|---|---|
| Manual   | 100,000,000 (20%) | OCR + scrape + transcription, repaired via `llm_quality_repair.py` |
| Downloaded | 400,000,000 (80%) | Wikipedia, IndicCorpV2, OSCAR, (Hindi: CC100 if enabled) |
| **Total** | **500,000,000** | |

These targets live in `manual_target_tokens` / `downloaded_target_tokens` /
`token_target` under `manual_collection:` in each language's
`configs/data_config.yaml`, and `manifest_utils.manual_downloaded_summary()`
checks both the absolute targets and the 20% ratio ??? `compute_stats.py`
prints a PASS/FAIL line for each. For **Nepali**, the 400M downloaded target
is aspirational (see the note in `nepali/configs/data_config.yaml`): if
public Nepali corpora don't reach it, do not backfill with invented manual
data ??? report the exact shortfall in the Phase 1 report instead, per the
assignment's instructions for the low-resource language.
